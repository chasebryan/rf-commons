# Safety Posture

RF Commons starts as a receive-only radio workbench.

The project should make lawful, public, educational listening easier without
building tooling for surveillance, privacy invasion, or unauthorized access.

## Boundaries

- No transmit features in the MVP.
- No cellular/private-signal decoding.
- No bypassing encryption.
- No harvesting private communications.
- No account requirement for basic listening or learning workflows.
- No telemetry by default.
- No ad-supported receiver directory.

## Product Defaults

- Prefer public, documented, educational, amateur, weather, aviation, and
  broadcast examples.
- Store bookmarks and logs locally unless the user explicitly exports them.
- Separate public receiver metadata from personal listening notes.
- Keep legal and licensing warnings near any future transmit-capable concept.
- Avoid presenting scanner-style workflows as surveillance tools.

## Integration Gate

Before hardware or remote-node integrations are marked production-ready, the
project should document:

- supported receive-only devices;
- where samples are processed;
- what is stored locally;
- what is transmitted over the network;
- whether the user is connected to a local receiver or a public receiver;
- which features are educational hints versus verified decoders.
